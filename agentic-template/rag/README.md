# Agentic RAG Template

A RAG (Retrieval-Augmented Generation) variant of the base agentic template.
Uses the same orchestrator-subagent-handoff architecture with RAG-specific phases and agents.

---

## What's Different from the Base Template

| Aspect | Base Template | RAG Variant |
|--------|--------------|-------------|
| **Context docs** | `data-sources.md`, `tech-stack.md` | `document-corpus.md`, `rag-stack.md` |
| **Phases** | Extract → Clean → Analyze → Model → Deliver | Ingest → Chunk ∥ Metadata → Embed → Index → Evaluate → Deliver |
| **Specialist agents** | Data science pipeline | RAG pipeline (see below) |
| **Quality gates** | File existence, row counts, notebook execution | + Vector dimension checks, retrieval recall thresholds, RAGAS score thresholds |
| **Evaluation infra** | None (results are outputs) | Ground-truth QA pairs required before indexing |

Shared with base template (unchanged):
- Planning prompts 0, 2, 3
- `code-quality.agent.md`, `code-simplifier.agent.md`, `code-reviewer.agent.md`
- Handoff JSON contract (extended with RAG metrics)
- Executor orchestration pattern

---

## Pipeline

```
Prompt 0 → Prompt 1 (RAG) → Prompt 2 → Prompt 3
                ↓
       executor.agent.md
          │
          ├── Phase 1:  corpus-ingester              → code-quality ✓
          ├── Phase 2:  chunker-preprocessor
          │             ∥ metadata-extractor          → code-quality ✓ (x2)
          ├── Phase 3:  embedder                     → code-quality ✓
          ├── Phase 4:  indexer                      → code-quality ✓
          ├── Phase 5:  retrieval-evaluator           → code-quality ✓
          ├── Phase 6:  generation-evaluator          → code-quality ✓
          └── Phase QA: code-simplifier → code-reviewer
```

## Pre-flight Checklist

These are the **runtime prerequisites** that will cause the pipeline to crash silently or hard-stop if missing. Unlike placeholder replacement (which you'll notice immediately when editing files), these are invisible until the executor fails.

Complete all six before running any prompt or agent:

| # | Prerequisite | How to verify | Blocking phase |
|---|---|---|---|
| 1 | `context-templates/document-corpus.md` filled in and copied to `docs/project-context/` | All `{PLACEHOLDER}` values replaced; at least one source in the Sources table | corpus-ingester (Phase 1) |
| 2 | `context-templates/rag-stack.md` filled in and copied to `docs/project-context/` | Embedding model, vector store, LLM, and chunk size all specified | Every agent |
| 3 | `docs/project-context/business-objectives.md` filled in | Goals, stakeholders, and success criteria present | Prompt 1 |
| 4 | All credentials set in `.env` | `python3 -c "from dotenv import load_dotenv; load_dotenv(); import os; print(os.getenv('EMBEDDING_API_KEY'))"` returns a non-null value | corpus-ingester Stage 0, embedder Stage 0 |
| 5 | Ground-truth QA eval set created at `{output-dir}/{task-id}/evaluation/qa_pairs.json` with ≥ 50 pairs | `python3 -c "import json; d=json.load(open('...qa_pairs.json')); assert len(d)>=50"` | Executor startup (hard-stop before Phase 1) |
| 6 | `evaluation/thresholds.yaml` reviewed and confirmed | Thresholds match your use case tolerance; blocking flags set appropriately | retrieval-evaluator (Phase 5), generation-evaluator (Phase 6) |

> **Item 5 is the most commonly missed.** The QA eval set is human work — it cannot be generated by an agent. Budget time for it before starting the pipeline. See `evaluation/qa-pairs-schema.json` for the required format.

## How to Use

1. Complete the [Pre-flight Checklist](#pre-flight-checklist) above
2. Copy `rag/` into your project's `.github/` directory alongside the base template files
3. Fill in `context-templates/document-corpus.md` and `context-templates/rag-stack.md`, then copy to `docs/project-context/`
4. Build the ground-truth QA eval set (≥ 50 pairs) before running any agent
5. Run `prompts/1-identify-rag-problems.prompt.md` instead of the base prompt 1
6. Run prompts 2 and 3 from the base template as normal
7. Run the RAG executor: `#executor.agent.md {task-id}`

---

## Minimum Eval Set Requirement

**A RAG pipeline without a ground-truth eval set cannot be validated.** Before running the executor, you must have:

- At least **50 question-answer pairs** where the answer is grounded in your corpus
- Questions that span different document types and topics in the corpus
- At minimum: question, expected answer, source document reference

See `evaluation/qa-pairs-schema.json` for the full schema.
